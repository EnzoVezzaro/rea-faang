The problem

The alternative exists. Nobody has mapped it.

Rented software is not owned software. Prices rise, features disappear, services shut down, and moving your data becomes somebody else's product decision. You cannot read the code, fix the bug, or keep the thing running after the company stops caring.

The usual advice — “just use an alternative” — arrives as a blog listicle. It names five tools, compares none, cites nothing, and goes stale within a year. What nobody publishes is the boring, useful thing: for this specific product, does an open-source replacement already exist, and if not, what exactly is missing?

Answering that question is step one. Building the missing pieces is step two.

  • Cited — every claim links a public source
  • Reproducible — every number has a command
  • Honest — “not built yet” is a valid answer
  • Clean room — public behavior and docs only
  • Reuse first — don't rebuild what exists

Objections, answered plainly

The reasons you're about to say no

Is any of this actually built yet?

No product implementations yet, and this page says so rather than hinting otherwise. What is built: the catalog, the research dossiers, the open-source map, the REA evidence, the tooling and a passing test suite — all reproducible from the repository today.

Isn't this just a list of other people's projects?

For 24 of 34 products, deliberately yes. Reusing Ceph instead of rewriting object storage is the whole point. The new work is the map, the specifications, and the products where no alternative exists at all.

How do you avoid copying proprietary code?

Clean room. Publicly observable behavior, official documentation and published protocols only. No decompilation, no proprietary source, no protected assets, no bypassing access controls.

Is this legal?

Product names are functional references; no affiliation or endorsement is implied. Implementations must respect applicable licenses and third-party rights. Rights holders can raise an issue on the repository.

Do I need to be an expert to contribute?

No. Pick a product, read its dossier and its skill file, then follow the pipeline. The entry points are in CONTRIBUTING.md.

Why should I trust the catalog?

Every claim cites a public source, the raw REA evidence is committed, and npm run validate plus the test suite run in CI on every push. If a number on this page goes stale, the command next to it will say so.
